# Pride Core Module 02 — 0.3.3-rc1 Staging Integration & Acceptance

**Status:** Work in progress. This milestone is not a finished, verified main campaign.  
**Target:** Fabric 1.21.1 / Cobblemon 1.8.1 / Java 21; FTB Quests + Per Player Quests.

## What's in this build

- **One cumulative Pride Core JAR**, Module 01 + Module 02.
- 27 server-side Pride Story NPC checkpoints; existing story.json is additive-upgraded with exact prechange backup, no user dialogue overwrite.
- 24 story-native NPC class/dialogue definitions, plus **three exact patches derived from League 7.10.10**. The patches retain existing Sequoia/Theo/Avery options and service actions; story syncing is an extra normal-option action.
- **Non-OP-compatible story command path:** native dialogue uses `q.player.run_command('pridecore story ...')`, without the former OP-only `execute as` wrapper. Needs non-OP in-game verification under Cobblemon 1.8.1.
- On-login idempotent reconciliation of verified starter, registration, kit markers. Requires previous story stage before writing, so it cannot regress a veteran from an advanced story stage. Doesn't grant items, badges, currency or FTB Quest progress.
- **Six generated additive FTB Quests chapters, 27 quests**, using Pride Core personal hidden advancements. Route 1 also checks existing real `prideregion:onboarding/first_catch_event` + `first_battle_event`; Gym/checkpoint stories require the corresponding **original** `prideregion:league/<type>` advancement, with Champion requiring `prideregion:league/champion`.
- Zero rewards in new FTB chapters: the existing League/Trainer systems remain sole award authorities.

## Exactly what to install on STAGING

1. Stop staging after **backing up the world, `mods/`, the world `datapacks/`, and `config/pride_core/` plus `config/ftbquests/quests/`**.
2. Replace only `pride-core-0.3.2-rc1.jar` with `pride-core-0.3.3-rc1.jar` (one Fabric mod ID).
3. Disable/remove the previous `PrideRegion_Story_Native_NPCs_0.3.2-rc1_STAGING.zip` from that staging world's datapacks. Put `PrideRegion_Story_Native_NPCs_0.3.3-rc1_STAGING.zip` in the same directory, keeping the untouched League 7.10.10 datapack and all other mods.
4. Start staging, inspect `/datapack list enabled`; enable the new story pack `last` above League if not already. Then run `/pridecore status`, `/pridecore story status`, `/pridecore story validate`.
5. The FTB pack is **separate and opt-in**. Unzip `PrideStoryFTB_0.3.3-rc1.zip` on your computer; copy the six `ftb_story_quest_overlay/chapters/*.snbt` files into `config/ftbquests/quests/chapters/`, checking that NONE of those chapter filenames or quest IDs already exists. Never overwrite existing quests, `data.snbt` or `chapter_groups.snbt`.
6. Append the lines from `PRIDE_STORY_EN_US_IMPORT.snbtfrag` **inside** your existing `config/ftbquests/quests/lang/en_us.snbt` root braces. No duplicate locale keys. Make a backup of that existing file first. A Quest book without an English locale file needs a valid SNBT root `{ ... }` first.
7. Per Player Quests is installed; ensure these chapters use its **per-player progression setting** instead of team-shared completion. The addon might require enabling per-player quest state in its GUI per quest/chapter. Do not assume simply having the mod installed makes this automatic.
8. Run `/ftbquests reload` on staging and review FTB Quests log for parse errors, missing advancement task types, unknown IDs, and hidden chapters. The generated file path/grammar follow FTB Quests 1.21.1 SNBT, but actual deployed modpack loading has **not** been verified.
9. Test a **fresh non-OP account**: Mom → Sequoia's original starter → Theo's original register → Avery's original kit, no extra story button or chat commands; then Route 1 genuine catch/battle event. Check `/pridecore story status`, quest journal, 27 advancements and absence of duplicate starter/kit/Impactor reward.
10. Test two players in separate parties, relog/restart, established player with legacy tags, existing Gym rewards, no extra Pokémon/items/currency/FTB completion; redo all before production deployment.

### Rollback

Stop staging. Remove the new JAR, new story pack and **only the six new FTB chapter files**. Restore the original `lang/en_us.snbt` and `config/pride_core` from backups if needed. Restore old JAR+pack together. Do not wipe player progression tags. The hidden advancements generated by this pack have no rewards, but removing them may cause FTB tasks referencing those IDs to appear unresolved until the tasks/chapters are also removed.

## Important unresolved production gates (Module 02 is not yet complete)

- Current native first-hour flow has been exercised primarily as OP/admin with previous builds. **Non-OP real-world validation is missing**. More importantly, League's *original* datapack functions still contain commands potentially permission-restricted for non-OP players; our new story command path alone cannot fix all upstream permissions.
- The *new* 24 native story actors use generic skins/portraits and are not yet properly placed in approved world locations, with collision/claim/instancing considerations.
- The six chapters implement a **reliable narrative journal**, not a complete mission objective system for every chapter. Story-specific location discovery, species-specific capture, authentic investigation/evidence items, trainer victory event hooks, reusable puzzle states, Rival team progression, multi-phase final boss and real facility crisis scenes are not yet implemented and tested.
- Some NPC dialogue `Continue our journey` choices remain placeholders for Acts I–V, and the crisis 'briefing' is not itself completion of a battle/boss/world incident.
- Only 27 quest checkpoint nodes and a few native victories are linked to FTB; the actual full questbook, side quests, complete original story authored scenes, map markers and proper game UX still need work.
- Finale/Champion/postgame must be integrated with the *real* League chronology and verified on an actual first-to-Champion playthrough. Do not retire the League 7.10.10 datapack until Module 03 replaces all its authorities.
